# Telegram-бот управления хабом

Бот живёт в `server/bot/`, запускается под PM2 как `portal-bot` (деплой-скрипты поднимают его
автоматически, если в `.env` задан `TELEGRAM_BOT_TOKEN`). Внешних npm-зависимостей нет —
long polling через Bot API на встроенном `fetch`.

## Команды

| Команда | Что делает |
|---|---|
| `/auth <пароль>` | Вход. Сессия действует 24 часа (`BOT_SESSION_TTL_HOURS`). Сообщение с паролем бот сразу удаляет. |
| `/status` | Загрузка сервера: load average, RAM, диск, uptime + таблица PM2-процессов (CPU/RAM/рестарты). |
| `/db` | Размер текущей БД, топ-10 таблиц, размеры всех видимых баз. |
| `/restart` | Быстрый перезапуск хаба: `pm2 restart portal` (без пересборки). С подтверждением. |
| `/redeploy` | Полное переразвёртывание: `scripts/deploy-all.sh` (git pull → ci → migrate → build → рестарт хаба и всех сервисов + Caddy). С подтверждением. |
| `/logs [имя] [строк]` | Последние логи PM2 (по умолчанию `portal`, 30 строк, максимум 100). |
| `/logout` | Завершить сессию досрочно. |

`/redeploy` запускается **отвязанным** процессом: деплой перезапускает и самого бота, но после
рестарта бот дочитывает лог (`data/bot-pending-deploy.json`) и присылает результат.

## Регистрация бота

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → задайте имя и username
   (например `myhub_ops_bot`). Получите токен вида `123456789:AA...`.
2. У BotFather же рекомендуется: `/setjoingroups` → **Disable** (бот работает только в личке и
   игнорирует группы на своей стороне, но лучше запретить и на стороне Telegram).
3. Узнайте свой Telegram user id — напишите боту [@userinfobot](https://t.me/userinfobot).
4. На сервере в каталоге хаба:

```bash
npm run bot:password -- 'ваш-пароль'   # напечатает строку BOT_PASSWORD_HASH=...
```

5. Добавьте в `.env` хаба:

```env
TELEGRAM_BOT_TOKEN=123456789:AA...
BOT_PASSWORD_HASH=scrypt$16384$8$1$...
TELEGRAM_ALLOWED_USER_IDS=ваш_id        # можно несколько через запятую
# BOT_SESSION_TTL_HOURS=24              # по умолчанию 24
```

6. Запустите бота (или просто прогоните деплой — он поднимет `portal-bot` сам):

```bash
pm2 start npm --name portal-bot -- run bot
pm2 save
```

7. Напишите боту `/auth ваш-пароль`.

Все `TELEGRAM_*` / `BOT_*` ключи — hub-only: при sync они **не копируются** в `.env` дочерних
сервисов.

## Безопасность (что уже сделано)

- **Пароль хранится только как scrypt-хеш** (`BOT_PASSWORD_HASH`), не в открытом виде.
- **Сессия на 24 часа**, состояние в `data/bot-state.json` (в `.gitignore`); `/logout` — досрочный сброс.
- **Allowlist по Telegram ID** (`TELEGRAM_ALLOWED_USER_IDS`): чужие пользователи игнорируются
  молча — им даже не отвечает, что бот существует. Настоятельно рекомендуется.
- **Лимит попыток пароля**: 5 неверных за 15 минут → блокировка входа на час.
- **Удаление сообщения с паролем** сразу после `/auth`.
- **Подтверждение кнопкой** для `/restart` и `/redeploy` (кнопка одноразовая, живёт 60 секунд,
  работает только для того, кто вызвал команду).
- **Аудит-лог** всех действий и отказов: `logs/bot-audit.log`.
- **Только личные чаты**: команды в группах игнорируются.
- **Один деплой за раз** — повторный `/redeploy` во время работающего отклоняется.

## Что ещё стоит учесть

- Не публикуйте username бота; токен и хеш — только в `.env` на сервере.
- Если токен утёк — `/revoke` у BotFather и замените в `.env`.
- Меняйте пароль периодически: `npm run bot:password -- 'новый'` → обновить `.env` → `pm2 restart portal-bot`.
- Возможные усиления, если понадобится: 2FA-подход (пароль + одноразовый код из логов сервера),
  webhook вместо polling за Caddy (сейчас не нужно — polling не открывает порты вообще),
  уведомление владельцу при неудачных попытках входа.

## Идеи для расширения

- Алерты: бот сам пишет, если какой-то PM2-процесс упал или диск заполнен > 90% (фоновая проверка раз в минуту).
- `/sync <сервис>` — пересинхронизировать один дочерний сервис (`npm run sync -- --only wallet`).
- `/backup` — `pg_dump` по запросу + отправка дампа файлом в чат.
- `/caddy` — статус Caddy и перегенерация конфига (`npm run sync:caddy`).
- Ежедневная сводка (`/status` + `/db`) по расписанию.
